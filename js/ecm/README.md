# Движок ECM для «Опасной зоны»

Здесь должен лежать файл `ecm-engine.js`. Пока его нет, кнопка «Начать» на странице экспериментов неактивна.

**ECM** (Enhanced Compression Model) — референсное ПО команды JVET (на C++). Готовой версии для браузера нет: её нужно собрать в WebAssembly (например, через Emscripten) и обернуть в Web Worker по контракту ниже. Перед публикацией сборки проверьте лицензию ECM.

## Контракт

`ecm-engine.js` — обычный (не module) Web Worker. Страница создаёт его через `new Worker(url)`.

Входящее сообщение (буферы передаются без копирования):

```js
{ cmd: 'encode',
  width: 640, height: 360,      // чётные
  fps: 15, qp: 32,
  config: 'ra',                 // 'ra' (Random Access) | 'ld' (Low Delay) | 'ai' (All Intra)
  threads: 2,                   // сколько потоков можно занять внутри этого воркера (1, если pthreads нет)
  segment: 0, segments: 4,      // номер сегмента и их общее число
  frames: [ArrayBuffer, ...] }  // кадры I420, 8 бит, BT.709 limited, плоскости Y, U, V подряд
```

Исходящие сообщения:

```js
{ type: 'progress', done: 3, total: 30 }
{ type: 'done', data: ArrayBuffer }        // поток ECM, лучше с transfer
{ type: 'error', message: '...' }
```

## Все ядра

Страница сама делит кадры на независимые сегменты и запускает по одному воркеру движка на сегмент (не больше 8). Каждый воркер кодирует свои кадры как отдельную последовательность, начинающуюся с точки произвольного доступа (IRAP), а страница склеивает готовые потоки по порядку. Поэтому движок должен работать с любым набором кадров независимо от соседних сегментов. Поле `threads` говорит, сколько потоков движок может взять сверх этого, если собран с pthreads.

## Замечания по сборке

- Страница умеет изолироваться (блок «Изолировать страницу» в опасной зоне, сервис-воркер `coi-sw.js` добавляет COOP/COEP), поэтому `SharedArrayBuffer` и pthread-сборка WebAssembly возможны. Без изоляции рассчитывайте на однопоточную сборку: параллелизм всё равно даёт разбивка на сегменты.
- Каждый воркер держит свой экземпляр движка в памяти, поэтому число сегментов ограничено объёмом ОЗУ (примерно 1,5 ГБ на сегмент).
- Конфиги кодировщика из репозитория ECM нужно вшить в виртуальную файловую систему движка.
- Результат — поток ECM, который воспроизведёт только декодер ECM.
